## Existing functionality, gaps and changes

The inspected repository started at v0.5.4 (integer 11). It already contained
five graphical Snap templates, `Meta.Window.move_resize_frame()`, live
compositor clones with activate/close/arrange actions, a configurable taskbar on
every monitor, monitor-change rebuild/rollback, negative-origin taskbar and
popup geometry, plus a MessageTray-backed notification center. Later v0.4.x and
v0.5.x functionality was preserved.

The remaining v0.3.0 reconciliation gaps were:

- Snap validated normalized geometry but did not inspect the client's minimum
  and maximum size constraints or verify the frame Mutter finally applied;
- a hover preview used the generic popup focus path, so merely hovering could
  replace the current Shell keyboard focus;
- leaving the taskbar button after the popup appeared neither bridged pointer
  movement into the preview nor closed an abandoned preview;
- minimized windows had only an incidental missing-texture fallback and
  activation did not explicitly unminimize them;
- close was always rendered instead of following `Meta.Window.can_close()`;
- multi-monitor and native-notification behavior had tests, but no focused SPEC
  0.3.0 contract or historical acceptance artifact.

v0.5.5 reads `get_min_size()`/`get_max_size()`, rejects an incompatible target,
and verifies `get_frame_rect()` asynchronously after Mutter applies the request.
An out-of-bounds result is moved into the work area when its size permits;
otherwise the user receives an error. Preview hover is now non-focusing and has
a short pointer bridge; Down Arrow opens a focusable preview, minimized windows
are labeled/unminimized, and close is capability-gated.

## Potential regressions and mitigations

- A client with restrictive maximum size can now reject a region that older code
  requested optimistically. This is intentional: the control reports inability
  instead of claiming an exact layout the application cannot honor.
- The delayed frame check is a 160 ms GLib source. Every pending source is owned
  by its Snap panel and removed on destroy; real slow Wayland clients still need
  validation and may settle later than this observation window.
- Pointer bridging uses a 180 ms close delay. It avoids a gap between actors but
  must be exercised under fractional scaling and accessibility pointer settings.
- Rebuilding all bars is deterministic and rollback-safe but can close open
  per-monitor flyouts during hotplug; preserving popup state is not required.
- MessageTray remains a GNOME Shell 46 internal API despite feature detection and
  the compatibility boundary.

## Manual GNOME 46 validation

1. Install v0.5.5 in a disposable Ubuntu 24.04 Wayland profile and keep the
   journal open while exercising native Wayland and XWayland windows.
2. Snap normal, minimum-size, maximum-size, fixed-size, dialog, maximized and
   minimized windows into every region on monitors with positive and negative
   origins. Confirm final frames never cross the current work area.
3. Hover taskbar apps and confirm focus stays in the previous app/taskbar item;
   move slowly and quickly between the icon and preview, then away from both.
4. Focus an app button by keyboard, press Down Arrow, traverse every preview
   action, press Escape and confirm focus returns to the originating button.
5. Activate and close normal/minimized windows; verify close is absent for any
   non-closable window and missing compositor textures show the icon fallback.
6. Toggle primary-only/all-monitors, hotplug/reorder displays, change primary
   monitor and repeat at 100%, 125%, 150% and 200% logical scale. Inspect for
   duplicate bars, stale struts, misplaced popups and leaked actors.
7. Enter fullscreen independently on every monitor; confirm taskbar/chrome
   tracking and restore behavior.
8. Generate, update, activate and dismiss notifications while hotplugging a
   monitor. Confirm GNOME remains authoritative and no item is persisted twice.
9. Repeat enable/disable ten times and inspect timers, signals, actors, chrome,
   focus and journal errors.
10. Repeat feasible checks on X11 and record protocol-specific differences.
