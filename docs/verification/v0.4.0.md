# WinShell — SPEC 0.4.0 graphical-Snap reconciliation

Date: 2026-11-08. Historical target: Ubuntu 24.04 LTS, GNOME Shell 46,
Wayland first. Reconciled in repository release v0.5.6 without downgrading or
removing newer functionality.

## Status

- static/unit/schema/XDG isolation: verified in the v0.5.6 reconciliation
- runtime GNOME 46/Wayland: pending
- runtime GNOME 46/X11: pending
- historical v0.4.0 release claim: unsupported; no contemporary runtime evidence
  establishes the tagged artifact as complete

## Existing functionality, gaps and changes

The inspected repository started at v0.5.5 (integer 12). It already exposed the
`snap-layouts` GSettings preference in GTK4/Libadwaita preferences, rendered the
five requested graphical diagrams, connected every eligible region to a real
`Meta.Window.move_resize_frame()` request, used the selected window's monitor
work area, handled negative origins, enforced client size limits and verified
the compositor result asynchronously. Context menus and window previews both
opened the picker. Later v0.4.x/v0.5.x system and appearance functionality was
preserved.

The remaining SPEC 0.4.0 reconciliation gaps were:

- template bounds, coverage and overlap were asserted ad hoc by one test rather
  than represented as a reusable pure contract;
- nested template/region data was mutable and duplicate template IDs had no
  validator;
- the graphical picker did not project client constraints before interaction,
  so an impossible region looked actionable until the click failed;
- Snap regions and preview mini-actions lacked explicit generated focus styles,
  and Snap regions lacked a distinct hover/unavailable state;
- there was no focused SPEC 0.4.0 contract or historical acceptance artifact.

During environment inspection, the journal of a separately installed copy also
showed repeated `Argument descendant may not be null` errors from popup
outside-click handling. The same source pattern existed in the repository, so
v0.5.6 now treats a missing event source as outside the popup instead of calling
`Clutter.Actor.contains(null)`. This fix is statically covered; the installed
copy was not replaced or retested by this work.

v0.5.6 freezes the five templates, validates unique IDs, finite normalized
bounds, complete coverage and non-overlap, and projects per-region rectangles or
`null` from client constraints. Every diagram remains visible, but incompatible
regions are non-reactive/non-focusable and described as unavailable; a picker
with no eligible region shows an explicit explanation. The executor revalidates
window state and geometry at click time. CSS is regenerated from design tokens
with focus/hover/unavailable states for the picker and focus/hover states for
preview controls.

## Potential regressions and mitigations

- Very constrained clients now show unavailable regions before a click. This is
  deliberate and does not change the executor's second validation, so a monitor
  or client-state change while the panel is open still fails safely.
- A disabled region remains visible at reduced opacity. Contrast and clarity at
  each visual preset and fractional scale require manual acceptance.
- A focus border may change the apparent segment inset. Pixel geometry concerns
  the target window and remains independent of diagram allocation; visual layout
  still needs GNOME Shell validation.
- `get_min_size()`/`get_max_size()` and final-frame behavior vary by native
  Wayland/XWayland client and remain runtime risks rather than claimed passes.

## Manual GNOME 46 validation

1. Install v0.5.6 in a disposable Ubuntu 24.04 GNOME 46 Wayland profile and
   keep `journalctl --user -f` open.
2. Toggle **Snap Layouts gráficos** off/on and verify the preview/context actions
   disappear/reappear without restarting the Shell.
3. Open all five diagrams from a taskbar context menu and from a window preview;
   verify halves, equal thirds, dominant left/right and quadrants are distinct.
4. Traverse every eligible region by keyboard, verify visible focus and restored
   focus after Escape; verify pointer hover and click match the highlighted region.
5. Snap a normal native Wayland and XWayland window into every region. Confirm
   the active window frame matches its current monitor work area and taskbar strut.
6. Repeat with fixed-size, restrictive minimum/maximum, maximized, minimized,
   fullscreen, dialog and non-resizable windows. Confirm unavailable/error states
   are honest and no unsupported mutation occurs.
7. Repeat on monitors with left/above negative origins and at 100%, 125%, 150%
   and 200% logical scale; inspect pixel gaps, overlaps and popup placement.
8. Switch primary monitor/hotplug while the picker is open, then click a region;
   confirm click-time revalidation prevents stale geometry.
9. Repeat enable/disable ten times and inspect actors, timers, focus, chrome,
   struts and journal errors. Repeat feasible checks on X11 and record differences.

## Rollback

Disable WinShell and run `./scripts/uninstall.sh`. To return to v0.5.5, install a
reviewed v0.5.5 artifact afterward. Inspect appearance divergence before forced
restoration; no schema key was added, removed or renamed by this reconciliation.
