## Existing functionality and gaps

The inspected repository started at metadata v0.5.1 (integer 8), with UUID
`winshell@iklav-tech`, GNOME 46-only metadata, GJS ES Modules, extension and
preferences entry points, GSettings, an MIT license, user-local install/remove
scripts and extensive feature modules. Cleanup paths already covered taskbar
actors/chrome, popups, signals, GLib sources, service callbacks, appearance
classes and reversible taskbar-extension state. These paths had static and pure
tests, but not a dedicated bootstrap contract or live Shell evidence.

The gaps found against SPEC 0.0.1 were:

- no `CONTRIBUTING.md` development and validation baseline;
- no `docs/verification/v0.0.1.md` separating retrospective evidence from a
  historical release claim;
- no single test protecting UUID, Shell version, ESM lifecycle, local paths,
  rollback guards and required repository documents;
- `install.sh --with-nautilus` checked optional dependencies only after writing
  core files, so a rejected optional integration could leave a partial install.

No GSettings key or existing feature implementation needed to be rebuilt.

## Potential regressions and mitigations

- The baseline was reconciled on top of v0.5.1 and metadata advanced to v0.5.2;
  no historical downgrade or schema migration occurred.
- Moving Nautilus checks earlier changes only failure ordering. The optional
  plugin is still copied after the core package when all prerequisites pass.
- Installer copies remain non-transactional for mid-write I/O failure; this is
  retained as R-03 and must not be represented as fully solved.
- Static source checks cannot prove GNOME actor or signal cleanup at runtime.

## Manual GNOME 46 validation

1. Run `./scripts/install.sh` in a disposable Ubuntu 24.04 user profile.
2. Sign out/in on Wayland and run
   `gnome-extensions info winshell@iklav-tech`.
3. Enable and disable WinShell ten times while watching the user journal.
4. After disable, verify no taskbar/popup actors, chrome, lower strut, focus grab,
   hidden native panel, managed dock state, signal or timeout remains.
5. Open preferences and confirm the installed schema and all pages load.
6. Run `./scripts/uninstall.sh`; confirm appearance restoration and removal only
   of WinShell-owned user-local paths.
7. Repeat the lifecycle smoke test under X11 where feasible and record differences.

## Rollback

For an installed copy:

```bash
gnome-extensions disable winshell@iklav-tech
./scripts/uninstall.sh
```

The uninstaller restores tracked appearance first and refuses external-change
conflicts. Review before using `--force-restore`; use `--no-restore` only when the
current appearance should intentionally remain. The appearance backup is retained
under `$XDG_CONFIG_HOME/winshell`.
